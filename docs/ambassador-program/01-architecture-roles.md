# Амбассадорская программа KazYouthDiplomacy — Архитектура и роли

Версия: 1.0 (MVP) · Дата: 2026-07-16

## 1. Общая схема системы

```
                        ┌─────────────────────────────┐
                        │   Сайт KazYouthDiplomacy     │
                        │   /ambassador.html           │
                        │   «Стать амбассадором»       │
                        └──────────────┬──────────────┘
                                       │ кнопка → t.me/<bot>?start=site
                                       ▼
┌──────────────────┐    webhook   ┌─────────────────────────────┐
│  Telegram Bot API │◄───────────►│  Express-сервер (server.js)  │
│  (личный кабинет  │              │  на Render                  │
│   амбассадора)    │              │  ├─ /api/tg/webhook  (бот)  │
└──────────────────┘              │  ├─ /api/amb/*  (админ-API) │
                                   │  ├─ /amb-admin/* (страницы) │
                                   │  └─ cron-задачи             │
                                   └──────────────┬──────────────┘
                                                  │
                                   ┌──────────────▼──────────────┐
                                   │   PostgreSQL (общая БД      │
                                   │   с Career GPS)             │
                                   │   таблицы amb_*             │
                                   └─────────────────────────────┘
```

**Ключевое решение:** система живет внутри существующего сервера и БД Career GPS.
Никакого отдельного сервиса. Это дает:

- нулевую дополнительную стоимость хостинга;
- интеграцию с Career GPS «бесплатно» во второй версии (общие пользователи, общая БД);
- один деплой, одна кодовая база.

Все новые таблицы получают префикс `amb_`, все новые API — префикс `/api/amb/`,
чтобы не смешиваться с существующим кодом.

## 2. Компоненты MVP

### 2.1 Страница «Стать амбассадором» (сайт)

Существующий `public/ambassador.html` перерабатывается: описание программы,
что получает и что должен амбассадор, шаги вступления, FAQ, кнопка
«Стать амбассадором» → `https://t.me/<bot_username>?start=site`.
Параметр `start` фиксирует источник регистрации (site / whatsapp / instagram / friend).

### 2.2 Telegram-бот (личный кабинет)

- Node-библиотека: **grammY** (современная, легкая, отлично работает через webhook
  внутри Express; альтернатива Telegraf — допустимо, но grammY проще для FSM).
- Режим: **webhook** `POST /api/tg/webhook/<secret>` — на Render это надежнее
  long polling и не требует отдельного процесса.
- Состояние диалога (анкета — многошаговый сценарий) хранится в БД
  (`amb_bot_states`), а не в памяти — сервер на Render может перезапускаться.
- Двуязычность: язык выбирается первым шагом, хранится в профиле; все тексты —
  в словаре `bot/i18n.js` (kz / ru), по образцу существующего `public/i18n.js`.

Функции бота в MVP: регистрация (анкета + направления + вводное задание),
верификация действующих амбассадоров, главное меню (профиль, команда, задания,
мероприятия, баллы, отчеты, помощь), сдача заданий, еженедельный отчет,
уведомления о статусе заявки и новых заданиях.

### 2.3 Административная панель

Новые страницы в `public/` по образцу существующей `admin-analytics.html`:

- `amb-admin.html` — дашборд + список участников;
- `amb-applications.html` — очередь заявок на рассмотрение;
- `amb-tasks.html` — создание заданий и проверка отчетов.

Вход через существующую сессионную авторизацию сайта (`users` + роль).
Тимлиды и координаторы получают аккаунты на сайте с программной ролью.

### 2.4 Фоновые задачи (cron)

По образцу существующего auto-expiry cron в server.js:

- понедельник утром — рассылка еженедельного отчета всем активным;
- ежедневно — напоминания о дедлайнах заданий и незавершенных анкетах;
- ежедневно — перевод в «давно не отвечает» при N недель без отчета;
- по дедлайну верификации — перевод неверифицированных из 370 в «резерв».

## 3. Идентичность пользователя

- **Первичный идентификатор амбассадора — `telegram_id`.** Бот и есть личный
  кабинет; email/пароль для амбассадора не нужны.
- Профиль амбассадора (`amb_profiles`) имеет **необязательную** ссылку
  `user_id → users` (аккаунт Career GPS). В MVP связь устанавливается по
  совпадению email/телефона (с подтверждением), в v2 — обязательный шаг
  «привяжи аккаунт Career GPS» для карьерных функций.
- Руководители (тимлид/координатор/Алиби) для админ-панели используют аккаунт
  сайта (`users`), связанный с их `amb_profiles`.

## 4. Роли и права доступа

Роль в программе хранится в `amb_profiles.program_role` и синхронизирована
со структурой (тимлид всегда привязан к своей команде, координатор — к потоку).

| Право | Амбассадор | Тимлид | Координатор | Алиби (head) | Техадмин |
|---|---|---|---|---|---|
| Свой профиль, баллы, задания | ✔ | ✔ | ✔ | ✔ | ✔ |
| Видеть состав своей команды | ✔ (имена) | ✔ (полностью) | ✔ | ✔ | ✔ |
| Проверять отчеты по заданиям | — | своя команда | свой поток | все | все |
| Принимать еженедельные отчеты | — | своя команда | свой поток | все | все |
| Создавать задания | — | для своей команды | для потока | для всех | ✔ |
| Начислять/списывать баллы вручную | — | — | свой поток | ✔ | ✔ |
| Рассматривать заявки кандидатов | — | — | ✔ (назначенные) | ✔ | ✔ |
| Менять статус участника (лестница) | — | предлагать | предлагать | ✔ | ✔ |
| Назначать тимлидов/координаторов | — | — | — | ✔ | ✔ |
| Дашборд-аналитика | — | команда | поток | вся программа | вся |
| Экспорт данных, персональные данные | — | минимум | свой поток | ✔ | ✔ |
| Рассылки | — | своей команде | своему потоку | всем | ✔ |

Принципы:

1. **Данные видны только вниз по своей ветке.** Тимлид не видит чужие команды,
   координатор — чужие потоки.
2. **Повышение статуса — только head.** Тимлид/координатор нажимают
   «рекомендовать на повышение», решение за Алиби (защита от накруток).
3. **Каждое ручное изменение баллов и статусов пишется в историю**
   (`amb_status_history`, `amb_points_ledger`) с указанием, кто и почему.
4. Персональные данные несовершеннолетних видят только координатор+ и head.

## 5. Три независимых измерения статуса участника

Не смешивать — это три разных поля:

1. **Статус заявки** (`amb_applications.status`) — живет только до приема:
   `draft → submitted → in_review → needs_revision / interview → accepted / reserve / rejected`.
2. **Ступень лестницы** (`amb_profiles.program_role`):
   `candidate → trainee → ambassador → active → senior → teamlead → coordinator → alumni`.
3. **Статус активности** (`amb_profiles.activity_status`) — операционная метка:
   `active / probation / needs_support / unresponsive / recommended_promotion / suspended / reserve`.

## 6. Потоки данных (основные сценарии)

- **Новый кандидат:** сайт → бот `?start=site` → язык → согласия → анкета →
  треки → вводное задание → заявка `submitted` → координатор в админке
  рассматривает → бот шлет решение → при `accepted` head/координатор назначает
  поток и команду → бот знакомит с тимлидом.
- **Верификация из WhatsApp:** ссылка `?start=migrate` → сокращенный сценарий
  (телефон, обновление анкеты, треки, мини-тест, подтверждение) → сразу
  `program_role = ambassador`, без полного отбора.
- **Задание:** руководитель создает в админке → бот уведомляет целевую
  аудиторию → участник берет задание → сдает отчет (текст/фото/файл/ссылка) →
  тимлид проверяет → одобрено = баллы в ledger / отклонено = причина в бот.
- **Еженедельный отчет:** cron в понедельник → 5 вопросов в боте → сводка
  тимлиду; «нужна помощь» — мгновенное уведомление тимлиду.

## 7. Безопасность и персональные данные

- Согласия (ПД, правила, кодекс, рассылки) — отдельными галочками, факт и время
  фиксируются в БД (`amb_profiles.consents` JSONB).
- Участники < 18: флаг `is_minor`, поле контакта законного представителя и
  отдельное согласие представителя (в MVP — подтверждение чекбоксом + контакт,
  в v2 — формальная процедура).
- Телефон подтверждается через Telegram-кнопку «Поделиться контактом»
  (номер приходит от Telegram, а не вводится вручную — защита от фейков).
- Webhook защищен секретом в URL + проверкой `X-Telegram-Bot-Api-Secret-Token`.
- Экспорт ПД — только head/техадмин, действия логируются.
- Ambassador ID вида `KYD-0248` — порядковый номер, оформляется как членский
  номер сообщества (без фото-«удостоверений», имитирующих документы).

## 8. Что сознательно НЕ входит в MVP

Мобильное приложение; автоматическое распределение по командам (в MVP — вручную
в админке); автосертификаты; рейтинги; рекомендательный движок Career GPS;
кабинет работодателя; английский язык (закладываем структуру i18n, добавить —
дешево); оплаты. Всё это — v2/v3 по концепции.
